## Part 1 — Python and the QA Workflow (10 questions)

#### Q1. Why is Python a good fit for release QA scripts?

<details>
<summary>Show answer</summary>

Python is readable, has a large standard library, and has good tools for files, JSON, CSV, HTTP, and pytest. It is a good default when a check has several steps or needs data structures. A shell one-liner or a SQL query may still be simpler for a single operation.

</details>

#### Q2. What is the Python interpreter?

<details>
<summary>Show answer</summary>

The interpreter is the program that reads and runs Python code. You start it with `python` or `python3`; it can run a file or an interactive session. The interpreter version matters because syntax and libraries differ across versions.

</details>

#### Q3. How do you run a Python script from the terminal?

<details>
<summary>Show answer</summary>

Run `python check_cards.py` (or `python3 check_cards.py`) from the folder that contains the script. The script's exit status tells CI whether it succeeded; a non-zero status means failure. Use an absolute path or change directory deliberately when the script reads relative files.

</details>

#### Q4. What is a virtual environment?

<details>
<summary>Show answer</summary>

A virtual environment is an isolated Python installation for one project. It keeps that project's packages separate from the system Python and other projects. Create one with `python -m venv .venv`, activate it, and install dependencies there.

</details>

#### Q5. What is `pip` used for?

<details>
<summary>Show answer</summary>

`pip` installs Python packages. Use `python -m pip install pytest requests` inside the active virtual environment. Record the dependencies in `requirements.txt` so another person can recreate the environment.

</details>

#### Q6. Why record dependencies in `requirements.txt`?

<details>
<summary>Show answer</summary>

The file lets another person or CI install the same packages without guessing. It also makes version changes reviewable. Regenerate or update it deliberately when a dependency changes.

</details>

#### Q7. What is a sensible small Python QA project layout?

<details>
<summary>Show answer</summary>

A common layout is a script at the root, tests under `tests/`, fixtures under `data/`, and `requirements.txt` at the root. Keep production data out of the fixture folder. The goal is that a reviewer can find the test, the data, and the dependency list quickly.

</details>

#### Q8. How does an `import` find a local module?

<details>
<summary>Show answer</summary>

Python searches the script's directory, the active environment, and the paths in `PYTHONPATH` and `sys.path`. A local module next to the script is usually found. If it is not, check the working directory and whether the file is on the path.

</details>

#### Q9. Where does pytest fit in a QA workflow?

<details>
<summary>Show answer</summary>

pytest runs the test functions in `tests/`. It discovers files named `test_*.py` and functions named `test_*`, reports failures, and returns a non-zero status when a test fails. CI can run `pytest` as a release gate.

</details>

#### Q10. When is a shell command a better choice than a Python script?

<details>
<summary>Show answer</summary>

Use a shell command for a single operation such as copying a file, checking a port, or filtering a log. Use Python when the logic has branches, data structures, parsing, or needs to be tested. Do not turn a one-line command into a fifty-line script without a reason.

</details>

## Part 2 — Values and Variables (10 questions)

#### Q11. What is the difference between an `int` and a `float`?

<details>
<summary>Show answer</summary>

An `int` is a whole number and a `float` is a number with a decimal part. `12` is an int; `4.25` is a float. Be explicit when a CSV string needs conversion: `int("12")` works, but `int("4.5")` raises `ValueError`.

</details>

#### Q12. How do you format a string with a variable in Python?

<details>
<summary>Show answer</summary>

Use an f-string: `print(f"Found {count} cards")`. The expression inside the braces is evaluated and inserted. f-strings are readable and are the usual choice in modern Python.

</details>

#### Q13. What is the difference between `False`, `0`, and `None`?

<details>
<summary>Show answer</summary>

`False` is a boolean, `0` is a number, and `None` means no value. They are different values even though all three are falsy in a condition. Use `is None` when you mean “missing,” and `== 0` when you mean zero.

</details>

#### Q14. When would you use a list?

<details>
<summary>Show answer</summary>

Use a list for an ordered collection you may change: cards in a file, rows from a CSV, or collected failures. Lists support `append`, indexing, and iteration. If the shape must never change, a tuple may be clearer.

</details>

#### Q15. When would you use a tuple?

<details>
<summary>Show answer</summary>

Use a tuple for a fixed group of values, such as `(question, answer)`. Tuples are immutable, so they cannot be appended to or reassigned by index. They are useful when the pair's shape is part of the meaning.

</details>

#### Q16. What is a dictionary good for?

<details>
<summary>Show answer</summary>

A dictionary maps keys to values, so it is a natural record: `{"id": 1, "question": "What is DNA?"}`. Look up a field by key. A missing key raises `KeyError`; use `.get("key")` when the field may be absent.

</details>

#### Q17. What is a set good for?

<details>
<summary>Show answer</summary>

A set stores unique values and is useful for duplicate checks: `len(set(questions))`. It loses order, so do not use it when position matters. Convert it back to a sorted list if you need a stable report.

</details>

#### Q18. How does indexing and slicing work?

<details>
<summary>Show answer</summary>

Indexes start at 0; `cards[0]` is the first item and `cards[-1]` is the last. A slice `cards[1:3]` takes indexes 1 and 2; the stop is exclusive. `cards[:2]` starts at the beginning, and `cards[2:]` goes to the end.

</details>

#### Q19. Why do CSV values need type conversion?

<details>
<summary>Show answer</summary>

CSV readers return strings, so `"12"` is not the number `12`. Convert with `int()` or `float()` before arithmetic or numeric comparison. Validate first and give a clear error when the value is not a number.

</details>

#### Q20. Why can mutability cause a bug?

<details>
<summary>Show answer</summary>

A list or dictionary passed to a function can be changed by that function, affecting the caller's data. Tuples and strings are immutable, so they cannot be changed in place. Copy a list with `list(items)` when the function should not mutate the original.

</details>

## Part 3 — Control Flow and Functions (10 questions)

#### Q21. When do you use `if`, `elif`, and `else`?

<details>
<summary>Show answer</summary>

Use them to choose a branch based on a condition. `if` handles the first case, `elif` handles additional cases, and `else` handles the fallback. Keep the conditions close to the product rule so the branch is understandable.

</details>

#### Q22. What does “truthiness” mean in Python?

<details>
<summary>Show answer</summary>

A value can be treated as true or false in a condition. Empty lists, empty strings, `0`, and `None` are falsy; non-empty containers are truthy. Explicit comparisons are often clearer when the difference between `None`, `0`, and `False` matters.

</details>

#### Q23. How do you loop over a list?

<details>
<summary>Show answer</summary>

Use `for card in cards:` to visit each item. Use `enumerate(cards, start=1)` when you also need the position. Avoid changing the list while iterating; build a new list or loop over a copy.

</details>

#### Q24. What does `range(3)` produce?

<details>
<summary>Show answer</summary>

`range(3)` produces `0`, `1`, and `2`; the stop is exclusive. `range(1, 4)` produces `1`, `2`, and `3`. Use it when the number of iterations comes from a count rather than a collection.

</details>

#### Q25. When is a `while` loop appropriate?

<details>
<summary>Show answer</summary>

Use `while` when the loop should continue until a condition changes, such as a retry with a limit. Make sure something inside the loop changes the condition. If you know the maximum number of attempts, a `for` loop over `range()` is often clearer.

</details>

#### Q26. What do `break` and `continue` do?

<details>
<summary>Show answer</summary>

`break` exits the loop immediately. `continue` skips the rest of the current iteration and moves to the next one. Use them sparingly; too many can make the loop hard to follow.

</details>

#### Q27. How do you define and call a function?

<details>
<summary>Show answer</summary>

Define it with `def name(parameters):` and an indented body; call it with `name(arguments)`. A function should have one clear job. Give it a name that describes the result, such as `count_cards` or `find_duplicates`.

</details>

#### Q28. What is a default argument?

<details>
<summary>Show answer</summary>

A default argument supplies a value when the caller does not provide one: `def normalize(text, lower=True):`. It makes an option explicit and keeps simple calls short. Avoid mutable defaults such as `items=[]`, because the same list can be shared across calls.

</details>

#### Q29. Why is returning a value better than printing inside a function?

<details>
<summary>Show answer</summary>

A returned value can be asserted on, printed by the caller, or written to a report. A function that only prints is harder to test and reuse. Return the result and let the caller decide what to do with it.

</details>

#### Q30. How do you import a helper from a local module?

<details>
<summary>Show answer</summary>

Put the helper in a file such as `helpers.py` and use `from helpers import count_cards`. The file must be on the script's path, usually in the same directory or under the package layout. Keep module names lowercase with underscores.

</details>
