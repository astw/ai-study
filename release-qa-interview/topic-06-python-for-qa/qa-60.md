60 open questions on the Python basics a junior release QA engineer needs.
Answers are hidden so you can attempt each question first. Examples use the
flashcards project and synthetic data. Every snippet is syntax-checked only; no
test or script was executed for this bank.

## Part 1 — Python and the QA Workflow (10 questions)

#### Q1. Why is Python a good fit for release QA scripts?

<details>
<summary>Show answer</summary>

Python is readable, has a large standard library, and has good tools for files, JSON, CSV, HTTP, and pytest. It is a good default when a check has several steps or needs data structures. A shell one-liner or a SQL query may still be simpler for a single operation.

</details>

#### Q2. What is the Python interpreter?

<details>
<summary>Show answer</summary>

The interpreter is the program that reads and runs Python code. You start it with `python` or `python3`; it can run a file or an interactive session. The interpreter version matters because syntax and libraries differ across versions.

</details>

#### Q3. How do you run a Python script from the terminal?

<details>
<summary>Show answer</summary>

Run `python check_cards.py` (or `python3 check_cards.py`) from the folder that contains the script. The script's exit status tells CI whether it succeeded; a non-zero status means failure. Use an absolute path or change directory deliberately when the script reads relative files.

</details>

#### Q4. What is a virtual environment?

<details>
<summary>Show answer</summary>

A virtual environment is an isolated Python installation for one project. It keeps that project's packages separate from the system Python and other projects. Create one with `python -m venv .venv`, activate it, and install dependencies there.

</details>

#### Q5. What is `pip` used for?

<details>
<summary>Show answer</summary>

`pip` installs Python packages. Use `python -m pip install pytest requests` inside the active virtual environment. Record the dependencies in `requirements.txt` so another person can recreate the environment.

</details>

#### Q6. Why record dependencies in `requirements.txt`?

<details>
<summary>Show answer</summary>

The file lets another person or CI install the same packages without guessing. It also makes version changes reviewable. Regenerate or update it deliberately when a dependency changes.

</details>

#### Q7. What is a sensible small Python QA project layout?

<details>
<summary>Show answer</summary>

A common layout is a script at the root, tests under `tests/`, fixtures under `data/`, and `requirements.txt` at the root. Keep production data out of the fixture folder. The goal is that a reviewer can find the test, the data, and the dependency list quickly.

</details>

#### Q8. How does an `import` find a local module?

<details>
<summary>Show answer</summary>

Python searches the script's directory, the active environment, and the paths in `PYTHONPATH` and `sys.path`. A local module next to the script is usually found. If it is not, check the working directory and whether the file is on the path.

</details>

#### Q9. Where does pytest fit in a QA workflow?

<details>
<summary>Show answer</summary>

pytest runs the test functions in `tests/`. It discovers files named `test_*.py` and functions named `test_*`, reports failures, and returns a non-zero status when a test fails. CI can run `pytest` as a release gate.

</details>

#### Q10. When is a shell command a better choice than a Python script?

<details>
<summary>Show answer</summary>

Use a shell command for a single operation such as copying a file, checking a port, or filtering a log. Use Python when the logic has branches, data structures, parsing, or needs to be tested. Do not turn a one-line command into a fifty-line script without a reason.

</details>

## Part 2 — Values and Variables (10 questions)

#### Q11. What is the difference between an `int` and a `float`?

<details>
<summary>Show answer</summary>

An `int` is a whole number and a `float` is a number with a decimal part. `12` is an int; `4.25` is a float. Be explicit when a CSV string needs conversion: `int("12")` works, but `int("4.5")` raises `ValueError`.

</details>

#### Q12. How do you format a string with a variable in Python?

<details>
<summary>Show answer</summary>

Use an f-string: `print(f"Found {count} cards")`. The expression inside the braces is evaluated and inserted. f-strings are readable and are the usual choice in modern Python.

</details>

#### Q13. What is the difference between `False`, `0`, and `None`?

<details>
<summary>Show answer</summary>

`False` is a boolean, `0` is a number, and `None` means no value. They are different values even though all three are falsy in a condition. Use `is None` when you mean “missing,” and `== 0` when you mean zero.

</details>

#### Q14. When would you use a list?

<details>
<summary>Show answer</summary>

Use a list for an ordered collection you may change: cards in a file, rows from a CSV, or collected failures. Lists support `append`, indexing, and iteration. If the shape must never change, a tuple may be clearer.

</details>

#### Q15. When would you use a tuple?

<details>
<summary>Show answer</summary>

Use a tuple for a fixed group of values, such as `(question, answer)`. Tuples are immutable, so they cannot be appended to or reassigned by index. They are useful when the pair's shape is part of the meaning.

</details>

#### Q16. What is a dictionary good for?

<details>
<summary>Show answer</summary>

A dictionary maps keys to values, so it is a natural record: `{"id": 1, "question": "What is DNA?"}`. Look up a field by key. A missing key raises `KeyError`; use `.get("key")` when the field may be absent.

</details>

#### Q17. What is a set good for?

<details>
<summary>Show answer</summary>

A set stores unique values and is useful for duplicate checks: `len(set(questions))`. It loses order, so do not use it when position matters. Convert it back to a sorted list if you need a stable report.

</details>

#### Q18. How does indexing and slicing work?

<details>
<summary>Show answer</summary>

Indexes start at 0; `cards[0]` is the first item and `cards[-1]` is the last. A slice `cards[1:3]` takes indexes 1 and 2; the stop is exclusive. `cards[:2]` starts at the beginning, and `cards[2:]` goes to the end.

</details>

#### Q19. Why do CSV values need type conversion?

<details>
<summary>Show answer</summary>

CSV readers return strings, so `"12"` is not the number `12`. Convert with `int()` or `float()` before arithmetic or numeric comparison. Validate first and give a clear error when the value is not a number.

</details>

#### Q20. Why can mutability cause a bug?

<details>
<summary>Show answer</summary>

A list or dictionary passed to a function can be changed by that function, affecting the caller's data. Tuples and strings are immutable, so they cannot be changed in place. Copy a list with `list(items)` when the function should not mutate the original.

</details>

## Part 3 — Control Flow and Functions (10 questions)

#### Q21. When do you use `if`, `elif`, and `else`?

<details>
<summary>Show answer</summary>

Use them to choose a branch based on a condition. `if` handles the first case, `elif` handles additional cases, and `else` handles the fallback. Keep the conditions close to the product rule so the branch is understandable.

</details>

#### Q22. What does “truthiness” mean in Python?

<details>
<summary>Show answer</summary>

A value can be treated as true or false in a condition. Empty lists, empty strings, `0`, and `None` are falsy; non-empty containers are truthy. Explicit comparisons are often clearer when the difference between `None`, `0`, and `False` matters.

</details>

#### Q23. How do you loop over a list?

<details>
<summary>Show answer</summary>

Use `for card in cards:` to visit each item. Use `enumerate(cards, start=1)` when you also need the position. Avoid changing the list while iterating; build a new list or loop over a copy.

</details>

#### Q24. What does `range(3)` produce?

<details>
<summary>Show answer</summary>

`range(3)` produces `0`, `1`, and `2`; the stop is exclusive. `range(1, 4)` produces `1`, `2`, and `3`. Use it when the number of iterations comes from a count rather than a collection.

</details>

#### Q25. When is a `while` loop appropriate?

<details>
<summary>Show answer</summary>

Use `while` when the loop should continue until a condition changes, such as a retry with a limit. Make sure something inside the loop changes the condition. If you know the maximum number of attempts, a `for` loop over `range()` is often clearer.

</details>

#### Q26. What do `break` and `continue` do?

<details>
<summary>Show answer</summary>

`break` exits the loop immediately. `continue` skips the rest of the current iteration and moves to the next one. Use them sparingly; too many can make the loop hard to follow.

</details>

#### Q27. How do you define and call a function?

<details>
<summary>Show answer</summary>

Define it with `def name(parameters):` and an indented body; call it with `name(arguments)`. A function should have one clear job. Give it a name that describes the result, such as `count_cards` or `find_duplicates`.

</details>

#### Q28. What is a default argument?

<details>
<summary>Show answer</summary>

A default argument supplies a value when the caller does not provide one: `def normalize(text, lower=True):`. It makes an option explicit and keeps simple calls short. Avoid mutable defaults such as `items=[]`, because the same list can be shared across calls.

</details>

#### Q29. Why is returning a value better than printing inside a function?

<details>
<summary>Show answer</summary>

A returned value can be asserted on, printed by the caller, or written to a report. A function that only prints is harder to test and reuse. Return the result and let the caller decide what to do with it.

</details>

#### Q30. How do you import a helper from a local module?

<details>
<summary>Show answer</summary>

Put the helper in a file such as `helpers.py` and use `from helpers import count_cards`. The file must be on the script's path, usually in the same directory or under the package layout. Keep module names lowercase with underscores.

</details>

## Part 4 — Files and Data (10 questions)

#### Q31. What is `pathlib.Path` used for?

<details>
<summary>Show answer</summary>

`Path` represents a file or directory path and provides methods such as `.exists()`, `.read_text()`, `.write_text()`, and `.parent`. It handles path joining portably: `Path("data") / "cards.md"`. It is usually clearer than manual string concatenation.

</details>

#### Q32. Why use `with open(...)` instead of calling `open` and `close` separately?

<details>
<summary>Show answer</summary>

`with` closes the file even if an exception occurs. That prevents leaked file handles and incomplete writes. It is the standard pattern for reading or writing files.

</details>

#### Q33. Why pass `encoding="utf-8"` when reading text?

<details>
<summary>Show answer</summary>

The default encoding can differ by platform. Passing UTF-8 explicitly makes the script behave the same on Windows, macOS, and Linux, and avoids errors on non-ASCII text. Use the encoding the fixture actually uses.

</details>

#### Q34. How do you parse JSON in Python?

<details>
<summary>Show answer</summary>

Use `json.loads(text)` to parse a string or `json.load(file)` to parse a file. The result is a Python dictionary or list. A `JSONDecodeError` means the input is not valid JSON; show the fixture and the error position.

</details>

#### Q35. How do you read a CSV file into dictionaries?

<details>
<summary>Show answer</summary>

Use `csv.DictReader` with a file opened using `newline=""`. Each row becomes a dictionary keyed by the header. Values are strings, so convert numbers explicitly. `list(reader)` materializes the rows when you need them more than once.

</details>

#### Q36. When do you use `try` and `except`?

<details>
<summary>Show answer</summary>

Use them around an operation that can fail in a way you can handle, such as a missing fixture or a malformed value. Catch the specific exception, then recover or raise a clear message. Avoid a bare `except:` that hides every error.

</details>

#### Q37. Why is a bare `except:` a problem?

<details>
<summary>Show answer</summary>

It catches every exception, including programming errors and interrupts, and can hide the real cause. A test may appear to handle a failure when it actually swallowed a bug. Catch the narrow exception you expect.

</details>

#### Q38. When should you use `logging` instead of `print`?

<details>
<summary>Show answer</summary>

Use `logging` when a script runs in CI, needs levels, timestamps, or a record that can be filtered. `print` is fine for a small local script. Never log secrets, tokens, or customer data.

</details>

#### Q39. What should a file-validation failure message include?

<details>
<summary>Show answer</summary>

Include the file path, the row or key, the expected value, and the actual value. A message such as “cards.csv row 4: expected a question, found an empty string” lets the next person reproduce and fix the problem.

</details>

#### Q40. How do you test a missing file case?

<details>
<summary>Show answer</summary>

Point the code at a path that does not exist, expect the specific exception or exit message, and assert that the message names the file. Do not create the file accidentally in the test. Use a temporary directory so the test cannot affect real fixtures.

</details>

## Part 5 — Testing with pytest (10 questions)

#### Q41. How does pytest discover tests?

<details>
<summary>Show answer</summary>

pytest discovers files named `test_*.py` or `*_test.py` and functions named `test_*` inside them. Run `pytest` from the project root. A test file with a clear name and focused functions is easiest to run and review.

</details>

#### Q42. What makes a good assertion message?

<details>
<summary>Show answer</summary>

It states the rule and the actual value: `assert count == 3, f"Expected 3 cards, found {count}"`. The message should help a reviewer understand what failed without reading the whole test. Avoid messages that only repeat the expression.

</details>

#### Q43. When do you use `pytest.raises`?

<details>
<summary>Show answer</summary>

Use it when the correct behavior is an exception, such as invalid input raising `ValueError`. Match the specific exception type. Do not use it to hide an unexpected failure that should be fixed.

</details>

#### Q44. What is a pytest fixture?

<details>
<summary>Show answer</summary>

A fixture prepares data or a resource for a test, such as a temporary file or a parsed fixture. A test requests it by naming it as an argument. Keep fixtures small and explicit so a failure is easy to trace.

</details>

#### Q45. What is `tmp_path`?

<details>
<summary>Show answer</summary>

`tmp_path` is a built-in pytest fixture that gives each test a temporary directory. Use it for files the test creates, so tests do not collide or leave artifacts. It is cleaned up by pytest.

</details>

#### Q46. What does `@pytest.mark.parametrize` do?

<details>
<summary>Show answer</summary>

It runs the same test function with several input/expected pairs. Each case appears separately in the output, so a failure identifies the input. It is useful for boundaries and data variations without copying the test.

</details>

#### Q47. How do you read a pytest failure?

<details>
<summary>Show answer</summary>

Read the test name, the failing line, the assertion, and the actual value. The first failure is usually the cause; later failures may be consequences. Re-run the single test to iterate quickly.

</details>

#### Q48. Why should tests be independent?

<details>
<summary>Show answer</summary>

An independent test does not depend on another test running first or on shared mutable state. It can run alone or in any order. Use fixtures and temporary directories to isolate setup and cleanup.

</details>

#### Q49. What should you not test with pytest?

<details>
<summary>Show answer</summary>

Do not use pytest to test a third-party library's behavior, the Python language, or a live production service without a controlled test endpoint. Test your code's behavior and the contract you depend on. Mock or isolate external services when needed.

</details>

#### Q50. How does pytest differ from unittest?

<details>
<summary>Show answer</summary>

`unittest` uses classes and `self.assert*` methods; pytest uses plain functions and `assert`, with fixtures and parametrization built in. pytest can run unittest-style tests too. For new small QA suites, pytest is usually shorter and easier to read.

</details>

## Part 6 — QA Scripting (10 questions)

#### Q51. How do you run another program from Python?

<details>
<summary>Show answer</summary>

Use `subprocess.run(["program", "arg"], capture_output=True, text=True)`. Pass a list of arguments rather than a shell string when possible. Check `returncode` or use `check=True` when a failure should raise.

</details>

#### Q52. Why check a subprocess return code?

<details>
<summary>Show answer</summary>

The return code tells you whether the program succeeded; `0` usually means success and non-zero means failure. A script that ignores it can report success after the command failed. Capture stdout and stderr for the report.

</details>

#### Q53. When is `argparse` useful in a QA script?

<details>
<summary>Show answer</summary>

Use it when a script needs a file path, an environment name, or a flag from the command line. It gives a clear `--help` and validates required arguments. For a one-off hard-coded check, it may be unnecessary.

</details>

#### Q54. How do you work with dates and times in Python?

<details>
<summary>Show answer</summary>

Use `datetime.now()` for the current time, `timedelta` for differences, and `strftime` for formatting. For comparisons across systems, use timezone-aware values. Avoid comparing naive local times from different machines.

</details>

#### Q55. How do you make an HTTP request in Python?

<details>
<summary>Show answer</summary>

Use `requests.get(url, timeout=5)` or `requests.post(...)`, then call `raise_for_status()` and parse `response.json()` if the body is JSON. Always set a timeout. The URL should point at a test environment, not production without approval.

</details>

#### Q56. Why set a timeout on an HTTP request?

<details>
<summary>Show answer</summary>

Without a timeout, a hung service can hang the test run indefinitely. A timeout turns the problem into a clear failure. Choose a value that fits the service's expected response time.

</details>

#### Q57. How do you avoid hard-coding a base URL?

<details>
<summary>Show answer</summary>

Read it from an environment variable, such as `os.environ.get("BASE_URL", "http://localhost:8000")`. Provide a safe local default and document the variable. Never hard-code a token or a production credential.

</details>

#### Q58. What should an end-to-end QA script check?

<details>
<summary>Show answer</summary>

Check the fixture or input, the action, and the observable result, with a clear failure at each step. Keep it idempotent and avoid destructive changes. Print or log enough context to reproduce a failure.

</details>

#### Q59. When should you not write a Python script?

<details>
<summary>Show answer</summary>

When a shell one-liner, a SQL query, or an existing test tool already does the job. A script adds maintenance, dependencies, and review surface. Write one when the logic is multi-step, reusable, or needs data structures and tests.

</details>

#### Q60. What makes a QA script trustworthy?

<details>
<summary>Show answer</summary>

It checks a real condition, fails with a clear message and non-zero status, avoids secrets, and is reproducible from the repository. It should not claim success without evidence. A reviewer should be able to run it and see the same result.

</details>
