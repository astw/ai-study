## Part 1 — SDLC Fundamentals and Models (30 questions)

### SDLC basics

#### MCQ 1. Which phase of the SDLC establishes what the product must do and the constraints it must meet?

A. Design
B. Requirements analysis
C. Implementation
D. Maintenance

<details>
<summary>Show answer</summary>

**Correct answer: B.** Requirements analysis defines the needed behavior and constraints. Design decides how to satisfy them, implementation builds the solution, and maintenance changes it after release.

</details>

#### MCQ 2. A team finds during system testing that a requirement conflicts with a regulatory rule. Which phase should have caught this first?

A. Requirements analysis
B. Implementation
C. System testing
D. Maintenance

<details>
<summary>Show answer</summary>

**Correct answer: A.** Requirement reviews should compare the requirement with regulatory constraints before design begins. Finding the conflict in system testing means the flaw was inherited by every later phase and must now be fixed late.

</details>

#### MCQ 3. What is the main difference between the SDLC and the STLC?

A. The SDLC is for developers, and the STLC is for testers.
B. The SDLC covers the product lifecycle; the STLC is the testing workstream inside it.
C. The STLC replaces the SDLC in Agile projects.
D. The SDLC ends at deployment; the STLC ends at test closure.

<details>
<summary>Show answer</summary>

**Correct answer: B.** The SDLC spans the product from concept to retirement, while the STLC is the testing lifecycle that runs alongside it. Option D is the nearest trap: both continue after deployment through maintenance and production feedback.

</details>

#### MCQ 4. Which STLC activity can begin during requirements analysis?

A. Test execution
B. Production monitoring
C. Test design and planning
D. Incident review

<details>
<summary>Show answer</summary>

**Correct answer: C.** Test design and planning can start as soon as requirements are reviewable, because acceptance criteria are what tests will be built from. Execution needs a build, and production monitoring and incident review happen after release.

</details>

#### MCQ 5. Why is "the testing phase" an incomplete description of QA work in an SDLC?

A. Testing only happens after deployment.
B. Testing is entirely automated.
C. QA only writes test cases.
D. QA also reviews requirements, designs tests, and prepares environments before execution.

<details>
<summary>Show answer</summary>

**Correct answer: D.** Test execution is only one part of QA work; reviews, test design, environment preparation, and regression planning happen across the lifecycle. Options A, B, and C are false absolutes that ignore those earlier and later activities.

</details>

#### MCQ 6. A release has a compressed test window because requirements were finalized late. Which lifecycle risk does this illustrate?

A. Too much test automation
B. Excessive regression coverage
C. Late feedback compressing verification time
D. Overstaffed QA

<details>
<summary>Show answer</summary>

**Correct answer: C.** Late requirements push design, development, and testing to the right, shrinking the time available for verification. The durable fix is earlier QA involvement and review, not simply compressing testing harder.

</details>

### Waterfall

#### MCQ 7. Which statement best describes the Waterfall model?

A. Overlapping iterations with continuous feedback
B. Sequential phases with approval gates and formal change control
C. Risk-driven loops with prototypes
D. Continuous deployment with feature flags

<details>
<summary>Show answer</summary>

**Correct answer: B.** Waterfall completes and approves each phase before the next one begins, with formal change control. Overlapping iterations describe iterative or Agile work, risk-driven loops describe the spiral model, and feature flags belong to continuous delivery.

</details>

#### MCQ 8. What is a typical QA disadvantage of Waterfall?

A. Too much early feedback
B. Requirements are never documented
C. Testing starts before design
D. Defects surface late and changes are expensive

<details>
<summary>Show answer</summary>

**Correct answer: D.** Waterfall usually places test execution after implementation, so requirement and design defects surface late and require expensive rework. Options A, B, and C invert the model: Waterfall documents heavily and tests late, not early.

</details>

#### MCQ 9. When is Waterfall most appropriate?

A. Requirements are stable and change is expensive
B. Requirements change every day
C. The team wants continuous delivery
D. The product is a throwaway prototype

<details>
<summary>Show answer</summary>

**Correct answer: A.** Waterfall fits stable, well-understood scope where change is costly and documentation matters. Rapidly changing requirements, continuous delivery, and throwaway prototypes all favor iterative or incremental approaches.

</details>

#### MCQ 10. A regulated hardware release has fixed contractual requirements and mandatory documentation. Which lifecycle fits best?

A. Waterfall
B. Pure Scrum with daily production releases
C. Exploratory testing with no plan
D. Continuous deployment with feature flags

<details>
<summary>Show answer</summary>

**Correct answer: A.** Fixed scope, expensive change, and documentation requirements align with Waterfall. The other options assume rapid change, frequent releases, or operational practices that the described constraints do not support.

</details>

### V-model

#### MCQ 11. In the V-model, which test level corresponds to the requirements phase?

A. Unit testing
B. Integration testing
C. System testing
D. Acceptance testing

<details>
<summary>Show answer</summary>

**Correct answer: D.** Requirements are verified by acceptance testing, system design by system testing, architecture by integration testing, and module design by unit testing. The V pairs each left-side development level with its right-side verification level.

</details>

#### MCQ 12. In the V-model, what is the main purpose of entry criteria?

A. To decide when a test level may start
B. To decide when a test level may finish
C. To assign defect priority
D. To select automation tools

<details>
<summary>Show answer</summary>

**Correct answer: A.** Entry criteria confirm the preconditions for starting a level, such as approved artifacts, a ready environment, and test data. Option B describes exit criteria, which decide when the level may finish.

</details>

#### MCQ 13. Which is a limitation of the V-model?

A. It cannot document requirements
B. It is sequential and handles late change poorly
C. It has no test levels
D. It forbids reviews

<details>
<summary>Show answer</summary>

**Correct answer: B.** The V-model's sequential structure means late requirement changes cascade through designs and tests. The other options are false: the model is documentation-heavy and explicitly defines test levels and reviews.

</details>

#### MCQ 14. A V-model team writes acceptance tests during requirements analysis. What is the main benefit?

A. It removes the need for system testing
B. It guarantees zero defects
C. It confirms the requirement is testable and plans the right level early
D. It replaces user acceptance testing

<details>
<summary>Show answer</summary>

**Correct answer: C.** Early acceptance-test design exposes ambiguous requirements and confirms that each requirement can be verified at the right level. It does not remove system testing, guarantee zero defects, or replace the act of user acceptance testing.

</details>

### Iterative, incremental, and spiral

#### MCQ 15. What is the difference between iterative and incremental development?

A. Iterative delivers functional slices; incremental repeats refinement cycles.
B. Iterative repeats refinement cycles; incremental adds functional slices.
C. They are identical.
D. Incremental is only for hardware.

<details>
<summary>Show answer</summary>

**Correct answer: B.** Iteration refines the product repeatedly, while increment adds functional slices; the two are often combined. Option A reverses the definitions, and option D is a false constraint.

</details>

#### MCQ 16. Which model is risk-driven and builds prototypes in repeated loops?

A. Waterfall
B. V-model
C. Spiral
D. Big-bang integration

<details>
<summary>Show answer</summary>

**Correct answer: C.** The spiral model runs repeated loops with explicit risk analysis, prototypes, and evaluation. Big-bang integration is an integration strategy, not a lifecycle model.

</details>

#### MCQ 17. In an incremental lifecycle, what must QA plan explicitly because no single increment owns it?

A. Unit test naming
B. Office seating
C. Source control branching
D. Cross-increment integration and end-to-end flows

<details>
<summary>Show answer</summary>

**Correct answer: D.** Each increment can pass its own tests while integration and end-to-end behavior break across increments. Those cumulative checks need an explicit owner and plan; the other options are unrelated to lifecycle risk.

</details>

#### MCQ 18. A product must deliver value early while requirements remain uncertain. Which approach fits best?

A. Waterfall with a long test phase
B. Iterative/incremental delivery with a growing regression suite
C. A single big-bang release at the end
D. Skipping regression to save time

<details>
<summary>Show answer</summary>

**Correct answer: B.** Uncertain requirements and a need for early value favor iterative, incremental delivery, with regression growing as the product grows. Waterfall and a single big-bang release delay feedback, and skipping regression accumulates risk.

</details>

### Agile and Scrum

#### MCQ 19. Which statement best describes Agile?

A. A fixed process with no planning
B. A set of values and principles emphasizing short feedback loops and working software
C. A test design technique
D. A replacement for the SDLC

<details>
<summary>Show answer</summary>

**Correct answer: B.** Agile is a set of values and principles; Scrum is one framework that implements them. Option A is a caricature, and options C and D confuse a mindset with a technique or lifecycle.

</details>

#### MCQ 20. In Scrum, who prioritizes the product backlog?

A. Scrum Master
B. QA lead
C. Product Owner
D. Developers

<details>
<summary>Show answer</summary>

**Correct answer: C.** The Product Owner owns the product backlog and its ordering. The Scrum Master facilitates the process, and the developers build the increment; neither owns backlog priority.

</details>

#### MCQ 21. What is the Scrum Master's main responsibility?

A. Writing all tests
B. Facilitating the process and removing impediments
C. Approving releases
D. Prioritizing the backlog

<details>
<summary>Show answer</summary>

**Correct answer: B.** The Scrum Master is a facilitator who helps the team follow Scrum and removes blockers. Prioritizing the backlog belongs to the Product Owner, and release approval is a business decision.

</details>

#### MCQ 22. Which Scrum ceremony is the best place for QA to size testing work and clarify acceptance criteria?

A. Daily Scrum
B. Sprint retrospective
C. Deployment
D. Sprint planning

<details>
<summary>Show answer</summary>

**Correct answer: D.** Sprint planning selects the work and is where acceptance criteria and testing effort are clarified. The Daily Scrum coordinates progress, the retrospective improves process, and deployment is not a Scrum ceremony.

</details>

#### MCQ 23. What is the definition of done used for?

A. Defining the shared quality checklist for a completed item
B. Listing all possible defects
C. Replacing acceptance criteria
D. Setting the release date

<details>
<summary>Show answer</summary>

**Correct answer: A.** The definition of done is the team's shared standard for completion, including testing and review expectations. Acceptance criteria describe specific behavior, and the definition of done neither lists defects nor sets release dates.

</details>

#### MCQ 24. A team marks a story done because the code is merged, but no tests ran and acceptance criteria are unverified. Which artifact should prevent this?

A. Product vision
B. Burndown chart
C. Definition of done
D. Risk register

<details>
<summary>Show answer</summary>

**Correct answer: C.** The definition of done should require tests and verified acceptance criteria before an item is called complete. A burndown chart tracks remaining work, not quality, and a vision or risk register does not gate completion.

</details>

#### MCQ 25. Which Scrum artifact contains the prioritized stories and acceptance criteria?

A. Sprint backlog
B. Increment
C. Definition of done
D. Product backlog

<details>
<summary>Show answer</summary>

**Correct answer: D.** The product backlog is the ordered list of stories and their acceptance criteria. The sprint backlog is the selected subset and tasks, the increment is the result, and the definition of done is the completion standard.

</details>

#### MCQ 26. In Scrum, why does delivering an increment every sprint not automatically mean a release?

A. Increments must still meet release criteria, dependencies, and cumulative risk.
B. Releases can only happen once a year.
C. QA cannot test in Scrum.
D. The Product Owner cannot decide scope.

<details>
<summary>Show answer</summary>

**Correct answer: A.** A release is a business and quality decision that considers cumulative regression, dependencies, non-functional readiness, and accepted risk. The other options are false rules that Scrum does not impose.

</details>

### Shift-left, shift-right, DevOps, and release vs deployment

#### MCQ 27. Which practice is an example of shift-left testing?

A. Canary releases in production
B. Post-incident reviews
C. Reviewing requirements and writing tests before code
D. Synthetic monitoring

<details>
<summary>Show answer</summary>

**Correct answer: C.** Shift-left moves quality activities earlier, such as requirement review and test design before implementation. Canary releases, incident reviews, and synthetic monitoring are shift-right or production feedback practices.

</details>

#### MCQ 28. Which practice is an example of shift-right testing?

A. Unit tests in continuous integration
B. Requirements review
C. Test data preparation
D. Canary release with production monitoring

<details>
<summary>Show answer</summary>

**Correct answer: D.** Shift-right validates behavior after release, in production and with real traffic; a monitored canary is a clear example. Unit tests, requirement reviews, and test data preparation are earlier, shift-left activities.

</details>

#### MCQ 29. How does DevOps most change the QA role?

A. QA builds quality into automated pipelines and uses production evidence.
B. QA stops testing entirely.
C. QA only writes manual scripts.
D. QA becomes the release owner.

<details>
<summary>Show answer</summary>

**Correct answer: A.** DevOps moves QA toward automated regression, quality gates, and production observability rather than late manual gatekeeping. Option D overstates the change; release accountability usually remains with product and business owners.

</details>

#### MCQ 30. A feature is deployed behind an off flag and enabled for 5% of users. What is the difference between deployment and release here?

A. Deployment and release are the same event.
B. Release happened before deployment.
C. Deployment moved the code; release makes it available to users.
D. The feature was never tested.

<details>
<summary>Show answer</summary>

**Correct answer: C.** Deployment places the artifacts in the environment, while release makes the functionality available to users; the flag decouples the two. Option A ignores the flag, and option B reverses the order.

</details>
