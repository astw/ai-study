## Part 1 — Orientation and System Information (8 questions)

#### Q1. What does `pwd` do, and how is it different from `cd`?

<details>
<summary>Show answer</summary>

`pwd` prints the current working directory, while `cd` changes it. Run `pwd` after a `cd` when you are unsure where a relative path will resolve. A failed `cd` leaves you in the old directory, so the check matters.

</details>

#### Q2. What do `ls -l`, `ls -a`, and `ls -h` show?

<details>
<summary>Show answer</summary>

`-l` uses the long format with permissions, owner, size, and time; `-a` includes hidden dotfiles; `-h` makes sizes human-readable. They are often combined as `ls -lah`. Use `-a` when checking configuration files that start with a dot.

</details>

#### Q3. What is the difference between `whoami` and `id`, and why does `sudo whoami` show root?

<details>
<summary>Show answer</summary>

`whoami` prints the effective username, while `id` also shows the user ID, group ID, and group memberships. Under `sudo`, the effective user is root, so `whoami` prints `root`. Use `id` or `logname` when you need the original account.

</details>

#### Q4. What does `uname` tell you, and what does `hostname` tell you?

<details>
<summary>Show answer</summary>

`uname` reports the operating system and kernel details; `uname -r` shows the kernel release. `hostname` reports the machine's name, and `hostname -f` tries the fully qualified name. Record both in a bug report when the environment may explain the failure.

</details>

#### Q5. How can `date` and `uptime` help in a test report?

<details>
<summary>Show answer</summary>

`date` gives a precise timestamp for when a test or log excerpt was captured. `uptime` shows how long the host has been running and its load averages, which helps explain a reboot or a slow run. A test host that rebooted during the run is a very different finding from a slow test.

</details>

#### Q6. What is the difference between `df` and `du`?

<details>
<summary>Show answer</summary>

`df` reports free space on mounted filesystems; `du` reports how much space files and directories use. Use `df -h` before a build and `du -sh artifacts/` when you need to find what is filling a volume. On Linux, `df -i` also checks inode exhaustion.

</details>

#### Q7. What does `free` show on Linux, and what would you use on macOS?

<details>
<summary>Show answer</summary>

`free` shows total, used, free, and available memory; `free -h` makes it readable. Linux counts cache in the memory figures, so read the `available` column. On macOS, use `vm_stat` and `top` instead.

</details>

#### Q8. What is the difference between `ps` and `top`, and how do you find a process by name?

<details>
<summary>Show answer</summary>

`ps` prints a snapshot of processes, while `top` shows a live, updating view. `ps aux` and `ps -ef` are common snapshots; `pgrep -af myapp` finds a process by name. Do not rely on `ps aux | grep myapp`, because the `grep` process matches too.

</details>

## Part 2 — Files and Folders (12 questions)

#### Q9. What does `mkdir -p` do that `mkdir` does not?

<details>
<summary>Show answer</summary>

`mkdir -p` creates any missing parent directories and does not fail if the final directory already exists. Plain `mkdir` fails when a parent is missing. Use `-p` for a path like `releases/2026-11-18/logs`.

</details>

#### Q10. What is `touch` used for?

<details>
<summary>Show answer</summary>

`touch` creates an empty file or updates an existing file's timestamps. `touch -c` avoids creating a file if it is missing. It is useful for placeholders and for testing sort or find behavior.

</details>

#### Q11. What do `cp -r` and `cp -p` do?

<details>
<summary>Show answer</summary>

`cp -r` copies directories recursively; `cp -p` preserves mode, ownership, and timestamps. Together they copy a directory while keeping its metadata. Check the result, because copying into an existing directory can nest it one level deeper.

</details>

#### Q12. What is the difference between copying and moving a file?

<details>
<summary>Show answer</summary>

`cp` leaves the original in place and creates a copy; `mv` removes the original and puts it at the new path. `mv` also renames. By default `mv` overwrites an existing destination, so use `-i` for important files.

</details>

#### Q13. Why is `rm -rf` dangerous, and how do you delete safely?

<details>
<summary>Show answer</summary>

`rm -rf` removes recursively and forces the deletion, with no trash or undo. A typo or an unresolved variable can delete far more than intended. Scope the path, prefer `rm -i` or a plain `rm` first, and never run it against `/` or an empty variable.

</details>

#### Q14. What does `ln -s` create, and how is it different from a hard link?

<details>
<summary>Show answer</summary>

`ln -s target link` creates a symbolic link, a small file that points at another path. A hard link makes a second directory entry for the same file data and cannot cross filesystems. Symlinks are common for a stable `current` build path.

</details>

#### Q15. How do you find files by name with `find`?

<details>
<summary>Show answer</summary>

Use `find path -name '*.zip'` to match a filename pattern, and add `-type f` to restrict to regular files. `-maxdepth` keeps the search from walking an entire tree. Quote the pattern so the shell does not expand it first.

</details>

#### Q16. How do you find files by size or modification time with `find`?

<details>
<summary>Show answer</summary>

`find artifacts -type f -size +100M` finds files larger than 100 MB. `find /var/log/myapp -type f -mtime -1` finds files modified in the last day. Check the units and the sign: `+` means greater than, and `-1` means less than one day old.

</details>

#### Q17. What does `stat` show, and how do the Linux and macOS formats differ?

<details>
<summary>Show answer</summary>

`stat` shows size, permissions, ownership, and timestamps. Linux uses `stat -c '%n %s %y' file`; macOS uses `stat -f '%N %z %Sm' file`. The `-c` and `-f` flags are not interchangeable, so scripts should branch by platform.

</details>

#### Q18. What does `file` tell you that `ls` does not?

<details>
<summary>Show answer</summary>

`file` reads a file's contents and reports its type, such as a zip archive, an ELF binary, or a shell script. `ls` shows names and metadata but not the content type. Use `file` to confirm an artifact is what the manifest claims.

</details>

#### Q19. What is the difference between an absolute and a relative path?

<details>
<summary>Show answer</summary>

An absolute path starts at `/` and does not depend on the current directory. A relative path starts from where you are, so the same command can resolve differently after a `cd`. `~` means your home directory, `.` means the current directory, and `..` means the parent.

</details>

#### Q20. How do globs and quoting work when a path contains spaces?

<details>
<summary>Show answer</summary>

The shell expands `*`, `?`, and `[abc]` before the command runs. A path with spaces must be quoted, as in `"artifacts/my build.zip"`, or the shell splits it into separate arguments. Quote variables too, such as `"$ARTIFACT_DIR"`, to avoid the same problem.

</details>

## Part 3 — Viewing and Searching Text and Logs (14 questions)

#### Q21. What is the difference between `cat` and `less`?

<details>
<summary>Show answer</summary>

`cat` prints the whole file at once, while `less` opens a pager that lets you scroll and search. Use `cat` for a short config and `less` for a large log. `cat` on a huge log floods the terminal.

</details>

#### Q22. How do you search inside `less`, and how do you quit?

<details>
<summary>Show answer</summary>

Type `/pattern` and press Enter to search forward; `n` goes to the next match. `G` jumps to the end, `g` to the start, and `q` quits. The pager does not modify the file.

</details>

#### Q23. What does `head` show?

<details>
<summary>Show answer</summary>

`head` prints the beginning of a file, and `head -n 20` prints the first 20 lines. It is useful for checking a log header, a CSV header, or a build manifest. It closes the pipe early, which can matter to a producer.

</details>

#### Q24. What does `tail` show?

<details>
<summary>Show answer</summary>

`tail` prints the end of a file; `tail -n 100` prints the last 100 lines. It is the standard way to see the most recent log entries. Combine it with `grep` to search only the recent window.

</details>

#### Q25. What is the difference between `tail -f` and `tail -F`?

<details>
<summary>Show answer</summary>

Both follow a file as it grows, but `-f` follows the open file and can stop when the file is rotated or truncated. `-F` follows the file name and reopens it after rotation. Use `-F` for a log that rotates during a long test.

</details>

#### Q26. What does `grep` do?

<details>
<summary>Show answer</summary>

`grep` searches text for a pattern and prints matching lines. It reads files or standard input, so it works well in a pipeline. It is the first tool for finding an error in a log.

</details>

#### Q27. What do `grep -i`, `-n`, `-r`, and `-v` do?

<details>
<summary>Show answer</summary>

`-i` ignores case, `-n` prints line numbers, `-r` searches directories recursively, and `-v` inverts the match. `grep -i error app.log` finds common case variants, and `grep -v health` removes noisy health-check lines.

</details>

#### Q28. What do the `grep` exit codes mean?

<details>
<summary>Show answer</summary>

`0` means at least one match was found, `1` means no match, and `2` means an error such as a bad pattern or unreadable file. A script must distinguish `1` from `2`; treating both as failure hides a real error. Check `$?` immediately after `grep`.

</details>

#### Q29. How does `wc -l` count lines, and what is the newline caveat?

<details>
<summary>Show answer</summary>

`wc -l` counts newline characters, not logical lines. A final line without a trailing newline is not counted. This is why a file that looks like it has 10 lines may report 9.

</details>

#### Q30. What do `cut -d` and `cut -f` do?

<details>
<summary>Show answer</summary>

`cut -d` sets the delimiter, and `cut -f` chooses the fields. For example, `cut -d',' -f2,3 report.csv` prints the second and third comma-separated fields. The delimiter is a single character.

</details>

#### Q31. What is the difference between `sort -n` and plain `sort`?

<details>
<summary>Show answer</summary>

Plain `sort` compares lines lexicographically, so `10` comes before `2`. `sort -n` compares numeric values. Use `-n` for counts and sizes, and `-k` with `-t` to sort by a specific field.

</details>

#### Q32. Why must input be sorted before `uniq`, and what does `uniq -c` show?

<details>
<summary>Show answer</summary>

`uniq` only collapses adjacent duplicate lines, so the input must be sorted first. `sort app.log | uniq -c` prints each unique line with its count. Add `sort -nr` to put the most frequent lines first.

</details>

#### Q33. What does `tee` do?

<details>
<summary>Show answer</summary>

`tee` sends its input to both standard output and a file. It lets you watch a test run while saving the output as evidence. `tee -a` appends instead of overwriting.

</details>

#### Q34. How would you build a log triage pipeline with `tail`, `grep`, `sort`, `uniq`, and `head`?

<details>
<summary>Show answer</summary>

Start with the recent window, filter the symptom, then count and rank it: `tail -n 1000 app.log | grep -i error | sort | uniq -c | sort -nr | head -n 20`. `tail` limits the scope, `grep` keeps error lines, `sort` groups them, `uniq -c` counts each group, the second `sort -nr` ranks the counts, and `head` shows the top 20.

</details>
