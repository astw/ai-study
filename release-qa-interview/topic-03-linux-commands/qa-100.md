## Part 1 — Orientation and System Information (8 questions)

#### Q1. What does `pwd` do, and how is it different from `cd`?

<details>
<summary>Show answer</summary>

`pwd` prints the current working directory, while `cd` changes it. Run `pwd` after a `cd` when you are unsure where a relative path will resolve. A failed `cd` leaves you in the old directory, so the check matters.

</details>

#### Q2. What do `ls -l`, `ls -a`, and `ls -h` show?

<details>
<summary>Show answer</summary>

`-l` uses the long format with permissions, owner, size, and time; `-a` includes hidden dotfiles; `-h` makes sizes human-readable. They are often combined as `ls -lah`. Use `-a` when checking configuration files that start with a dot.

</details>

#### Q3. What is the difference between `whoami` and `id`, and why does `sudo whoami` show root?

<details>
<summary>Show answer</summary>

`whoami` prints the effective username, while `id` also shows the user ID, group ID, and group memberships. Under `sudo`, the effective user is root, so `whoami` prints `root`. Use `id` or `logname` when you need the original account.

</details>

#### Q4. What does `uname` tell you, and what does `hostname` tell you?

<details>
<summary>Show answer</summary>

`uname` reports the operating system and kernel details; `uname -r` shows the kernel release. `hostname` reports the machine's name, and `hostname -f` tries the fully qualified name. Record both in a bug report when the environment may explain the failure.

</details>

#### Q5. How can `date` and `uptime` help in a test report?

<details>
<summary>Show answer</summary>

`date` gives a precise timestamp for when a test or log excerpt was captured. `uptime` shows how long the host has been running and its load averages, which helps explain a reboot or a slow run. A test host that rebooted during the run is a very different finding from a slow test.

</details>

#### Q6. What is the difference between `df` and `du`?

<details>
<summary>Show answer</summary>

`df` reports free space on mounted filesystems; `du` reports how much space files and directories use. Use `df -h` before a build and `du -sh artifacts/` when you need to find what is filling a volume. On Linux, `df -i` also checks inode exhaustion.

</details>

#### Q7. What does `free` show on Linux, and what would you use on macOS?

<details>
<summary>Show answer</summary>

`free` shows total, used, free, and available memory; `free -h` makes it readable. Linux counts cache in the memory figures, so read the `available` column. On macOS, use `vm_stat` and `top` instead.

</details>

#### Q8. What is the difference between `ps` and `top`, and how do you find a process by name?

<details>
<summary>Show answer</summary>

`ps` prints a snapshot of processes, while `top` shows a live, updating view. `ps aux` and `ps -ef` are common snapshots; `pgrep -af myapp` finds a process by name. Do not rely on `ps aux | grep myapp`, because the `grep` process matches too.

</details>

## Part 2 — Files and Folders (12 questions)

#### Q9. What does `mkdir -p` do that `mkdir` does not?

<details>
<summary>Show answer</summary>

`mkdir -p` creates any missing parent directories and does not fail if the final directory already exists. Plain `mkdir` fails when a parent is missing. Use `-p` for a path like `releases/2026-11-18/logs`.

</details>

#### Q10. What is `touch` used for?

<details>
<summary>Show answer</summary>

`touch` creates an empty file or updates an existing file's timestamps. `touch -c` avoids creating a file if it is missing. It is useful for placeholders and for testing sort or find behavior.

</details>

#### Q11. What do `cp -r` and `cp -p` do?

<details>
<summary>Show answer</summary>

`cp -r` copies directories recursively; `cp -p` preserves mode, ownership, and timestamps. Together they copy a directory while keeping its metadata. Check the result, because copying into an existing directory can nest it one level deeper.

</details>

#### Q12. What is the difference between copying and moving a file?

<details>
<summary>Show answer</summary>

`cp` leaves the original in place and creates a copy; `mv` removes the original and puts it at the new path. `mv` also renames. By default `mv` overwrites an existing destination, so use `-i` for important files.

</details>

#### Q13. Why is `rm -rf` dangerous, and how do you delete safely?

<details>
<summary>Show answer</summary>

`rm -rf` removes recursively and forces the deletion, with no trash or undo. A typo or an unresolved variable can delete far more than intended. Scope the path, prefer `rm -i` or a plain `rm` first, and never run it against `/` or an empty variable.

</details>

#### Q14. What does `ln -s` create, and how is it different from a hard link?

<details>
<summary>Show answer</summary>

`ln -s target link` creates a symbolic link, a small file that points at another path. A hard link makes a second directory entry for the same file data and cannot cross filesystems. Symlinks are common for a stable `current` build path.

</details>

#### Q15. How do you find files by name with `find`?

<details>
<summary>Show answer</summary>

Use `find path -name '*.zip'` to match a filename pattern, and add `-type f` to restrict to regular files. `-maxdepth` keeps the search from walking an entire tree. Quote the pattern so the shell does not expand it first.

</details>

#### Q16. How do you find files by size or modification time with `find`?

<details>
<summary>Show answer</summary>

`find artifacts -type f -size +100M` finds files larger than 100 MB. `find /var/log/myapp -type f -mtime -1` finds files modified in the last day. Check the units and the sign: `+` means greater than, and `-1` means less than one day old.

</details>

#### Q17. What does `stat` show, and how do the Linux and macOS formats differ?

<details>
<summary>Show answer</summary>

`stat` shows size, permissions, ownership, and timestamps. Linux uses `stat -c '%n %s %y' file`; macOS uses `stat -f '%N %z %Sm' file`. The `-c` and `-f` flags are not interchangeable, so scripts should branch by platform.

</details>

#### Q18. What does `file` tell you that `ls` does not?

<details>
<summary>Show answer</summary>

`file` reads a file's contents and reports its type, such as a zip archive, an ELF binary, or a shell script. `ls` shows names and metadata but not the content type. Use `file` to confirm an artifact is what the manifest claims.

</details>

#### Q19. What is the difference between an absolute and a relative path?

<details>
<summary>Show answer</summary>

An absolute path starts at `/` and does not depend on the current directory. A relative path starts from where you are, so the same command can resolve differently after a `cd`. `~` means your home directory, `.` means the current directory, and `..` means the parent.

</details>

#### Q20. How do globs and quoting work when a path contains spaces?

<details>
<summary>Show answer</summary>

The shell expands `*`, `?`, and `[abc]` before the command runs. A path with spaces must be quoted, as in `"artifacts/my build.zip"`, or the shell splits it into separate arguments. Quote variables too, such as `"$ARTIFACT_DIR"`, to avoid the same problem.

</details>

## Part 3 — Viewing and Searching Text and Logs (14 questions)

#### Q21. What is the difference between `cat` and `less`?

<details>
<summary>Show answer</summary>

`cat` prints the whole file at once, while `less` opens a pager that lets you scroll and search. Use `cat` for a short config and `less` for a large log. `cat` on a huge log floods the terminal.

</details>

#### Q22. How do you search inside `less`, and how do you quit?

<details>
<summary>Show answer</summary>

Type `/pattern` and press Enter to search forward; `n` goes to the next match. `G` jumps to the end, `g` to the start, and `q` quits. The pager does not modify the file.

</details>

#### Q23. What does `head` show?

<details>
<summary>Show answer</summary>

`head` prints the beginning of a file, and `head -n 20` prints the first 20 lines. It is useful for checking a log header, a CSV header, or a build manifest. It closes the pipe early, which can matter to a producer.

</details>

#### Q24. What does `tail` show?

<details>
<summary>Show answer</summary>

`tail` prints the end of a file; `tail -n 100` prints the last 100 lines. It is the standard way to see the most recent log entries. Combine it with `grep` to search only the recent window.

</details>

#### Q25. What is the difference between `tail -f` and `tail -F`?

<details>
<summary>Show answer</summary>

Both follow a file as it grows, but `-f` follows the open file and can stop when the file is rotated or truncated. `-F` follows the file name and reopens it after rotation. Use `-F` for a log that rotates during a long test.

</details>

#### Q26. What does `grep` do?

<details>
<summary>Show answer</summary>

`grep` searches text for a pattern and prints matching lines. It reads files or standard input, so it works well in a pipeline. It is the first tool for finding an error in a log.

</details>

#### Q27. What do `grep -i`, `-n`, `-r`, and `-v` do?

<details>
<summary>Show answer</summary>

`-i` ignores case, `-n` prints line numbers, `-r` searches directories recursively, and `-v` inverts the match. `grep -i error app.log` finds common case variants, and `grep -v health` removes noisy health-check lines.

</details>

#### Q28. What do the `grep` exit codes mean?

<details>
<summary>Show answer</summary>

`0` means at least one match was found, `1` means no match, and `2` means an error such as a bad pattern or unreadable file. A script must distinguish `1` from `2`; treating both as failure hides a real error. Check `$?` immediately after `grep`.

</details>

#### Q29. How does `wc -l` count lines, and what is the newline caveat?

<details>
<summary>Show answer</summary>

`wc -l` counts newline characters, not logical lines. A final line without a trailing newline is not counted. This is why a file that looks like it has 10 lines may report 9.

</details>

#### Q30. What do `cut -d` and `cut -f` do?

<details>
<summary>Show answer</summary>

`cut -d` sets the delimiter, and `cut -f` chooses the fields. For example, `cut -d',' -f2,3 report.csv` prints the second and third comma-separated fields. The delimiter is a single character.

</details>

#### Q31. What is the difference between `sort -n` and plain `sort`?

<details>
<summary>Show answer</summary>

Plain `sort` compares lines lexicographically, so `10` comes before `2`. `sort -n` compares numeric values. Use `-n` for counts and sizes, and `-k` with `-t` to sort by a specific field.

</details>

#### Q32. Why must input be sorted before `uniq`, and what does `uniq -c` show?

<details>
<summary>Show answer</summary>

`uniq` only collapses adjacent duplicate lines, so the input must be sorted first. `sort app.log | uniq -c` prints each unique line with its count. Add `sort -nr` to put the most frequent lines first.

</details>

#### Q33. What does `tee` do?

<details>
<summary>Show answer</summary>

`tee` sends its input to both standard output and a file. It lets you watch a test run while saving the output as evidence. `tee -a` appends instead of overwriting.

</details>

#### Q34. How would you build a log triage pipeline with `tail`, `grep`, `sort`, `uniq`, and `head`?

<details>
<summary>Show answer</summary>

Start with the recent window, filter the symptom, then count and rank it: `tail -n 1000 app.log | grep -i error | sort | uniq -c | sort -nr | head -n 20`. `tail` limits the scope, `grep` keeps error lines, `sort` groups them, `uniq -c` counts each group, the second `sort -nr` ranks the counts, and `head` shows the top 20.

</details>

## Part 4 — Processes and Services (12 questions)

#### Q35. How do you read the PID, PPID, and STAT columns in `ps`?

<details>
<summary>Show answer</summary>

`PID` is the process ID, and `PPID` is its parent's process ID; `ps -ef` shows both clearly. `STAT` is the process state: `R` running, `S` sleeping, `D` uninterruptible sleep, `T` stopped, and `Z` a zombie. A zombie or a process stuck in `D` often explains a hung test.

</details>

#### Q36. When would you use `ps -ef` instead of `ps aux`?

<details>
<summary>Show answer</summary>

`ps aux` is BSD style and is convenient for CPU and memory percentages; `ps -ef` is System V style and shows the PPID prominently. Use `-ef` when tracing a process tree, and `aux` when checking resource use. Both show all processes.

</details>

#### Q37. What do the key fields in `top` tell you?

<details>
<summary>Show answer</summary>

The summary shows load averages, task counts, CPU usage, and memory and swap. The process list shows PID, user, priority, virtual and resident memory, CPU and memory percentages, and the command. Use `top -b -n 1` on Linux or `top -l 1` on macOS for a snapshot you can save.

</details>

#### Q38. What does `kill` do, and what is the default signal?

<details>
<summary>Show answer</summary>

`kill` sends a signal to a process by PID; the default is `TERM`, which asks the process to stop cleanly. `kill -l` lists the signal names. Always confirm the PID before sending a signal.

</details>

#### Q39. What is the difference between TERM, KILL, and HUP?

<details>
<summary>Show answer</summary>

`TERM` asks the process to exit cleanly and can be caught; `KILL` forces it to stop and cannot be caught; `HUP` originally meant hangup and many services use it to reload configuration. Prefer `TERM`, then `KILL` only if the process will not exit.

</details>

#### Q40. How do `jobs`, `bg`, and `fg` work together?

<details>
<summary>Show answer</summary>

`Ctrl-Z` suspends the current job, `jobs` lists the shell's jobs, `bg %1` continues job 1 in the background, and `fg %1` brings it back to the foreground. They manage jobs started from the current shell. Job control does not behave the same way in a non-interactive script.

</details>

#### Q41. What does `jobs -l` add?

<details>
<summary>Show answer</summary>

`jobs -l` includes the process IDs as well as the job numbers. The PID lets you use `ps` or `kill` on the process directly. Without `-l`, you only see the shell's job numbers.

</details>

#### Q42. What does `systemctl status` show?

<details>
<summary>Show answer</summary>

It shows whether the unit is loaded, enabled, and active, the main PID, and the most recent log lines. It is the fastest check that a service is running. `--no-pager` prints the output directly for a log or a bug report.

</details>

#### Q43. How do you start, stop, and restart a service?

<details>
<summary>Show answer</summary>

Use `sudo systemctl start myapp`, `sudo systemctl stop myapp`, and `sudo systemctl restart myapp`. Check the result with `systemctl status myapp` or `systemctl is-active myapp`. Restarting a service is a state change; confirm it is part of the test or the runbook.

</details>

#### Q44. What does `journalctl -u myapp` show?

<details>
<summary>Show answer</summary>

It shows the journal entries for the `myapp` systemd unit, so you do not need to know which log file the service writes. `--no-pager` prints directly, and `-n 100` limits the output. It is Linux-only; macOS uses `log show`.

</details>

#### Q45. What do `-f`, `--since`, and `-p err` do in `journalctl`?

<details>
<summary>Show answer</summary>

`-f` follows new entries, `--since '1 hour ago'` limits the time window, and `-p err` shows error priority and above. They can be combined, as in `journalctl -u myapp --since '30 minutes ago' -p err`. The time filter keeps the output focused on the incident.

</details>

#### Q46. What is the difference between a process and a service?

<details>
<summary>Show answer</summary>

A process is a running program with a PID; a service is a background program managed by the init system, such as a systemd unit. One service can start several processes. `systemctl status` shows the unit, while `ps` shows the individual processes.

</details>

## Part 5 — Permissions and Ownership (10 questions)

#### Q47. How do you read a permission string from `ls -l`?

<details>
<summary>Show answer</summary>

The first character is the type: `-` for a file, `d` for a directory, `l` for a symlink. The next nine characters are three triples for owner, group, and others, each read, write, and execute. After that come the owner, group, size, modification time, and name.

</details>

#### Q48. What do the three rwx triples mean?

<details>
<summary>Show answer</summary>

The first triple applies to the owner, the second to the owning group, and the third to everyone else. `r` is read, `w` is write, and `x` is execute. For a directory, `x` means you can enter or traverse it.

</details>

#### Q49. How does symbolic `chmod` work?

<details>
<summary>Show answer</summary>

Symbolic mode names the audience (`u`, `g`, `o`, or `a`), an operator (`+`, `-`, or `=`), and the permissions (`r`, `w`, `x`). For example, `chmod u+x run-tests.sh` adds execute for the owner, and `chmod g-w config.yml` removes group write. It is readable when changing one permission at a time.

</details>

#### Q50. How does numeric `chmod` work?

<details>
<summary>Show answer</summary>

Each permission has a value: read is 4, write is 2, and execute is 1. Add them for each triple, so `755` is owner read/write/execute, group read/execute, and others read/execute. `644` is the common file default, and `755` is the common executable or directory mode.

</details>

#### Q51. What does `chown user:group file` do?

<details>
<summary>Show answer</summary>

It changes both the owner and the group of the file. `chown -R user:group dir` applies it recursively. Changing ownership usually requires root, so it is often run with `sudo`.

</details>

#### Q52. What is the difference between `chown` and `chgrp`?

<details>
<summary>Show answer</summary>

`chown` changes the owner and can also change the group; `chgrp` changes only the group. Use `chgrp qa logs/app.log` when the owner is already correct. You must be a member of the target group for `chgrp` to work.

</details>

#### Q53. What does `umask` control?

<details>
<summary>Show answer</summary>

`umask` sets the permissions removed from newly created files and directories. With `umask 022`, new files typically get 644 and directories 755. It subtracts permissions; it never adds them.

</details>

#### Q54. How does `id` help diagnose a permission problem?

<details>
<summary>Show answer</summary>

`id` shows your user ID, primary group, and group memberships. If a file is group-readable but you are not in the group, `id` shows why. `id -nG` prints the group names, which is easier to read than numeric IDs.

</details>

#### Q55. When should you use `sudo`, and what is the risk?

<details>
<summary>Show answer</summary>

Use `sudo` when a task genuinely requires root, such as restarting a system service or reading a root-owned log. It can create root-owned files, change system state, and hide permission problems that real users will hit. Prefer `sudo -u` for a specific user and avoid `sudo` around test commands by habit.

</details>

#### Q56. What causes `Permission denied`, and how do you diagnose it?

<details>
<summary>Show answer</summary>

Check whether your user has the needed read, write, or execute bit with `ls -l`, whether you are in the owning group with `id`, and whether a parent directory is traversable. A file can be readable but unreachable if a parent directory lacks execute. Fix the specific permission; do not use `chmod 777` as a shortcut.

</details>

## Part 6 — Disks, Memory, and Archives (10 questions)

#### Q57. How do `df` and `du` differ when a disk looks full?

<details>
<summary>Show answer</summary>

`df` reports free space on the filesystem; `du` reports how much space directories and files use. They can disagree when a deleted file is still held open by a process, because the space is not released until the process closes it. Check `df -h`, `df -i`, and `du -sh` on the directories you own.

</details>

#### Q58. What does the `available` column in `free -h` mean?

<details>
<summary>Show answer</summary>

`available` estimates how much memory can be given to new processes without swapping, including reclaimable cache. It is more useful than the `free` column, which can look small because Linux uses spare memory for cache. Check it before a load or soak test.

</details>

#### Q59. How do you create a `.tar.gz` archive?

<details>
<summary>Show answer</summary>

Use `tar -czf artifacts/app.tar.gz releases/2026-11-18`: `-c` creates, `-z` compresses with gzip, and `-f` names the archive. The archive path comes immediately after `-f`. List it before handing it off.

</details>

#### Q60. How do you list and extract a `.tar.gz` archive?

<details>
<summary>Show answer</summary>

`tar -tzf artifacts/app.tar.gz` lists the contents, and `tar -xzf artifacts/app.tar.gz -C /tmp/release` extracts them into a chosen directory. Listing first shows what will be written. `-C` keeps the extraction scoped instead of writing into the current directory.

</details>

#### Q61. What does `gzip -k` do, and why use it?

<details>
<summary>Show answer</summary>

`gzip -k` compresses the file and keeps the original. Without `-k`, gzip replaces the original with the `.gz` file. Keeping the original is useful when the log is evidence and you want to attach a smaller copy.

</details>

#### Q62. What is the difference between `zip` and `tar.gz`?

<details>
<summary>Show answer</summary>

`zip` is an archive and compression format with random access to individual files; `tar.gz` is a tar archive compressed as a stream. Zip is common on Windows, while tar.gz is common on Linux. Both are fine for artifacts; choose the one the consumer expects.

</details>

#### Q63. How do you verify an artifact checksum with `sha256sum`?

<details>
<summary>Show answer</summary>

Run `sha256sum artifacts/app.zip` and compare the value with the published checksum. If a checksum file is provided, `sha256sum -c checksums.txt` verifies every listed file. A mismatch is a release blocker until you understand why.

</details>

#### Q64. What is the macOS equivalent of `sha256sum`?

<details>
<summary>Show answer</summary>

macOS does not ship `sha256sum` by default; use `shasum -a 256 artifacts/app.zip`. The output is the same SHA-256 value. Install GNU coreutils with Homebrew if you want the `sha256sum` name.

</details>

#### Q65. Why compare a checksum with a trusted source rather than the file itself?

<details>
<summary>Show answer</summary>

A checksum stored next to the file proves only that the file matches that checksum, not that either is genuine. Compare with a value from a trusted release page, a signed manifest, or the vendor. The checksum proves integrity; the trusted source provides authenticity.

</details>

#### Q66. What are the first signs of a full disk, and how do you confirm it?

<details>
<summary>Show answer</summary>

Writes fail with `No space left on device`, logs stop growing, and tests fail while the application looks healthy. Confirm with `df -h`, check inodes with `df -i` on Linux, and find the largest directories with `du -sh`. Clean only files you are authorized to remove.

</details>

## Part 7 — Pipes, Redirection, Exit Codes, and Environment (8 questions)

#### Q67. What does the pipe `|` do?

<details>
<summary>Show answer</summary>

The pipe sends the standard output of one command into the standard input of the next. For example, `grep -i error app.log | wc -l` counts matching lines without a temporary file. The exit status of a pipeline is the status of its last command unless the shell enables `pipefail`.

</details>

#### Q68. What is the difference between `>` and `>>`?

<details>
<summary>Show answer</summary>

`>` writes standard output to a file and overwrites it; `>>` appends. Both create the file if it does not exist. Use `>>` for a log you want to keep across runs.

</details>

#### Q69. What does `2>` do?

<details>
<summary>Show answer</summary>

`2>` redirects standard error to a file while leaving standard output on the terminal. For example, `./run-tests.sh 2> errors.log` keeps the normal output visible and saves the errors. It is useful when you want to separate the two streams.

</details>

#### Q70. What does `2>&1` do, and why does order matter?

<details>
<summary>Show answer</summary>

`2>&1` sends standard error to the same destination as standard output. In `> file 2>&1`, both streams go to the file; in `2>&1 > file`, stderr goes to the old stdout (the terminal) and only stdout goes to the file. Put the redirection of stdout first when you want both.

</details>

#### Q71. What does `$?` contain, and how do you check it?

<details>
<summary>Show answer</summary>

`$?` holds the exit status of the last command: `0` means success, and any non-zero value means failure. Check it immediately with `echo $?` before running another command. In a pipeline, it reflects the last command unless `pipefail` is set.

</details>

#### Q72. What does `env` show, and why should you redact it?

<details>
<summary>Show answer</summary>

`env` prints the environment variables for the current process, and `env | sort` makes them easier to scan. The output can include tokens, passwords, and internal URLs. Redact secrets before attaching it to a ticket or a chat.

</details>

#### Q73. What does `export` do, and how long does it last?

<details>
<summary>Show answer</summary>

`export VAR=value` sets a variable for the current shell and the child processes it starts. The change lasts for that shell session and does not persist after it exits. Use `unset VAR` to remove it, and add permanent settings to your shell profile only when appropriate.

</details>

#### Q74. What is `PATH`, and how does command lookup work?

<details>
<summary>Show answer</summary>

`PATH` is a colon-separated list of directories the shell searches for a command. The first matching executable wins, so order matters when two directories contain the same name. `command -v curl` shows which executable would run.

</details>

## Part 8 — SSH and File Transfer (10 questions)

#### Q75. What does `ssh user@host` do?

<details>
<summary>Show answer</summary>

It opens an encrypted remote shell on the host, authenticating with a key or password. The session is protected by SSH, and the host key is checked on first connection. An SSH config alias can supply the user, host, key, and port.

</details>

#### Q76. How do you run one command on a remote host without an interactive session?

<details>
<summary>Show answer</summary>

Put the command in quotes after the host: `ssh user@host 'tail -n 20 /var/log/myapp/app.log'`. The output comes back to your terminal, and the remote command's exit status is returned. Quote carefully so the local shell does not expand variables meant for the remote side.

</details>

#### Q77. What does `ssh-keygen` create, and how do you protect the private key?

<details>
<summary>Show answer</summary>

It creates a public and private key pair, such as an ed25519 key. The public key goes into the server's `authorized_keys`, and the private key stays on your machine at mode `600`. Never share, commit, or paste the private key; use a passphrase when possible.

</details>

#### Q78. What is `~/.ssh/config` used for?

<details>
<summary>Show answer</summary>

It stores host aliases and connection settings such as `HostName`, `User`, `IdentityFile`, and `Port`. Then `ssh staging` expands to the full connection without retyping flags. Keep the file and keys at mode `600`.

</details>

#### Q79. How do you copy a file to a remote host with `scp`?

<details>
<summary>Show answer</summary>

Use `scp artifacts/app.zip user@host:/tmp/` for a file, and add `-r` for a directory. `-P` sets the port (uppercase) and `-p` preserves timestamps (lowercase). Verify the copy on the remote side before deleting the local source.

</details>

#### Q80. When would you use `sftp` instead of `scp`?

<details>
<summary>Show answer</summary>

Use `sftp` when you want an interactive session to browse, upload, and download several files with `ls`, `put`, and `get`. For a single file, `scp` is shorter. SFTP runs over SSH on port 22; it is not FTPS.

</details>

#### Q81. What does `rsync -avz` do, and what does a trailing slash on the source mean?

<details>
<summary>Show answer</summary>

`-a` preserves permissions and times, `-v` shows transfers, and `-z` compresses in transit. A trailing slash on the source copies its contents into the destination; without it, the source directory itself is copied. Use `-n` first to dry-run.

</details>

#### Q82. What is SSH port forwarding, and when would a tester use it?

<details>
<summary>Show answer</summary>

SSH can forward a local port through a remote host, for example `ssh -L 8080:internal-host:80 user@jump-host`. A tester uses it to reach a service on a private network without exposing it publicly. Only do this with authorization, and keep the forwarded port scoped.

</details>

#### Q83. What does `Permission denied (publickey)` mean, and how do you debug it?

<details>
<summary>Show answer</summary>

The server rejected your key, so the issue is authentication, not the network. Check that the key file exists and is mode `600`, that the right key is offered (`ssh -v`), and that the public key is in the server's `authorized_keys`. `ssh-add -l` shows which keys the agent holds.

</details>

#### Q84. What does a host-key verification warning mean, and what should you do?

<details>
<summary>Show answer</summary>

The server's host key is unknown or has changed since the last connection. Verify the fingerprint through a trusted channel before accepting it. If the change is legitimate, remove the old `known_hosts` entry; do not blindly accept a changed key, because it can indicate a man-in-the-middle.

</details>

## Part 9 — curl and Network Checks (8 questions)

#### Q85. What does `curl -I` do?

<details>
<summary>Show answer</summary>

`curl -I` sends a HEAD request and prints the response headers without the body. It is a quick smoke check for status, content type, cache headers, and redirects. It still performs the DNS, TCP, and TLS steps.

</details>

#### Q86. What does `curl -v` show?

<details>
<summary>Show answer</summary>

It shows DNS resolution, the TCP connection, the TLS handshake, the request headers, the response status, and the response headers. The error wording separates a name failure, a refused port, a timeout, and a certificate problem. It is the best single command for an HTTP-level bug.

</details>

#### Q87. How do you send a POST with a JSON body in `curl`?

<details>
<summary>Show answer</summary>

Use `curl -X POST -H 'Content-Type: application/json' -d '{"status":"ok"}' https://example.com/api`. `-d` supplies the body, and `-H` sets the content type. Quote the JSON so the shell does not split it.

</details>

#### Q88. How do you make `curl` time out and retry?

<details>
<summary>Show answer</summary>

Add `--max-time 10 --retry 2` to cap the request and retry transient failures. Check the exit status and the response rather than assuming a retry succeeded. For a long download, consider `--retry-delay` and a resumable download.

</details>

#### Q89. What does `ping -c 4` test, and what does it not prove?

<details>
<summary>Show answer</summary>

It sends four ICMP echo requests and reports loss and round-trip time. It proves basic reachability and latency, not that a service port is open or the application is healthy. A blocked ICMP can make ping fail while TCP works.

</details>

#### Q90. How do you check a DNS record with `dig`?

<details>
<summary>Show answer</summary>

Run `dig example.com`, or `dig +short example.com` for the answer only. Use `@resolver` to query a specific server and a type such as `A`, `AAAA`, or `MX`. Compare two resolvers when a name works in one place but not another.

</details>

#### Q91. What does `ss -tulpn` show?

<details>
<summary>Show answer</summary>

It shows TCP and UDP listening sockets with numeric ports and process IDs. It answers whether the service is listening on the expected port. `ss` is Linux-only; macOS uses `netstat` or `lsof -i`.

</details>

#### Q92. What does `nc -vz host 443` test?

<details>
<summary>Show answer</summary>

It tries a TCP connection to port 443 and reports whether it succeeds or fails. `-z` scans without sending data, and `-v` adds detail. Netcat variants differ, so `curl` or `ss` may be more reliable on a given host.

</details>

## Part 10 — Release QA Workflows (8 questions)

#### Q93. What do you check before releasing an artifact?

<details>
<summary>Show answer</summary>

Confirm the artifact exists, has the expected size, matches its checksum, and contains the expected files. Use `ls -lh`, `sha256sum`, `tar -tzf` or `unzip -l`, and `file`. A missing or unexpected file list is a release blocker until explained.

</details>

#### Q94. How do you verify an artifact checksum in a release workflow?

<details>
<summary>Show answer</summary>

Compare the computed checksum with the value published by a trusted source, such as a signed manifest or the release page. `sha256sum -c checksums.txt` verifies a list in one step. A mismatch is a blocker, not a warning.

</details>

#### Q95. How do you triage a service log during a release?

<details>
<summary>Show answer</summary>

Start with the recent window: `journalctl -u myapp --since '30 minutes ago' -p err`, or `tail -n 200 app.log | grep -i error`. Correlate the timestamp with the failing test, and save the exact excerpt as evidence. Use `less` for a large file instead of dumping it.

</details>

#### Q96. How do you confirm a service is active and listening?

<details>
<summary>Show answer</summary>

Check the service with `systemctl status myapp` or `systemctl is-active myapp`, then check the port with `ss -tulpn` or an endpoint with `curl -I`. A unit can be active while the port is not listening, so check both. Restart only when the test or runbook says to.

</details>

#### Q97. How do you check a port and an HTTP endpoint?

<details>
<summary>Show answer</summary>

Use `ss -tulpn` to see the listener, `nc -vz host 443` to test TCP reachability, and `curl -I https://host/health` to check the HTTP status and headers. A closed port, a refused connection, and a 500 response are different findings. Capture the command output for the report.

</details>

#### Q98. How do you check permissions and disk space before a long test run?

<details>
<summary>Show answer</summary>

Use `ls -l` and `id` to confirm the test user can read logs and write artifacts, and `df -h` plus `df -i` to confirm space and inodes. `du -sh` shows what is already using the volume. Fix a full or unwritable volume before blaming the application.

</details>

#### Q99. What belongs in a release-day checklist?

<details>
<summary>Show answer</summary>

Check the artifact and checksum, disk space, service status, listening port, and health endpoint. Then run the smoke or regression suite with output saved, record the exit code, and note residual risk. The checklist ties the individual commands to a repeatable decision.

</details>

#### Q100. What should you record in a test summary after the run?

<details>
<summary>Show answer</summary>

Record the build and environment, what was tested and what was not, results against the exit criteria, open defects, evidence paths, command exit codes, and residual risk. Include a clear recommendation for the release decision. The summary should let someone else reconstruct what happened without rerunning everything.

</details>
